Kev: API de Classification Open-Source pour les PME Suisses — Routage de Tickets, Documents & Décisions Sans API Payantes

kevclassificationprotection-des-données

Chaque semaine apporte un nouveau service IA avec un prix, et pour les PME suisses et les indépendants, les coûts peuvent s'accumuler rapidement. Pourtant, nombreuses tâches de routine — routage d'e-mails clients, catégorisation de factures, priorisation de tickets d'assistance — n'ont besoin que d'une classification simple, pas d'un modèle complet. Kev est une API de classification open-source que vous pouvez faire tourner vous-même, avec des tailles de 0,8B à 27B paramètres, où le modèle 4B est le modèle de prédilection qui s'exécute sur une GPU de laptop ou même un CPU pour les charges de travail de base.

\n\n

Que fait Kev exactement

\n\n

Kev répond oui/non, choix multiples ou questions de notation à propos d'un texte et retourne des probabilités calibrées en un seul passage. Il est construit pour le routage de tickets, la modération et la classification — pas pour la génération de texte libre. Pensez à lui comme à une alternative wire-kompatible aux services IA payants, sauf que vous l'hébergez vous-même ou que vous faites tourner le modèle 4B localement sur une machine que vous possédez.

\n\n

Trois tâches qui rapportent en premier

\n\n

Dans notre travail avec des freelances suisses, des notaires, des médecins et de petites entreprises, trois tâches de classification rapportent presque toujours l'effort :

\n\n
    \n
  • Routage de tickets. Les e-mails clients entrants ou les demandes de support peuvent être automatiquement dirigés vers l'équipe appropriée ou marqués pour suivi en fonction du contenu.
    • \n
  • Catégorisation de documents. Contrats, lettres et devis peuvent être classés par type, urgence ou action requise — sans envoyer les données clients vers une API cloud.
    • \n
  • Soutien à la décision. Devis, propositions ou listes de contrôle de conformité peuvent être scannés et résumés en une notation oui/non, vous aidant à décider rapidement sans lire chaque mot.
    • \n
\n\n

Commencez par exactement une de ces tâches. Une tâche, un canal, un gain clair.

\n\n

Quelle taille de modèle avez-vous vraiment besoin

\n\n

Kev expédie quatre tailles ensemble sous le nom de « Kev 1.0 » : 0,8B, 4B (le modèle recommandé par défaut), 9B et 27B. Sur des données « new source » held-out, le benchmark interne du projet place Kev-27B à 0,851 exactitude contre Jev's 0,857 — un écart d'un point par leur propre mesure. Pourtant, per le README, Kev-4B sur un H100 répond à six questions en 18,1 ms de temps de modèle, et un conteneur sert environ 101 requêtes par seconde. Le modèle 4B est celui qui s'exécute localement pour de nombreux cas d'utilisation, et il devance la précision du 27B d'un seul point — mais si vous n'avez pas de GPU, le modèle 0,8B peut tout de même classifier des documents simples, bien que plus lentement.

\n\n

La règle de données qui vous protège

\n\n

Avant de coller quoi que ce soit dans un outil, une règle compte : traitez les données clients comme confidentielles, même dans un chatbot sympathique. Selon la loi suisse sur la protection des données (LPD), ne saisissez pas d'informations identifiables — noms, notes médicales, détails financiers — dans un outil grand public sans vérifier. La solution pratique est simple : anonymisez ou remplacez d'abord les éléments identifiants, et pour les travaux sensibles en médecine, droit ou finance, utilisez une solution approuvée ou locale. L'API wire-compatible de Kev signifie que vous pouvez faire tourner le modèle 4B sur une infrastructure que vous contrôlez, en gardant vos données sur site.

\n\n

Voilà la version honnête du “commencer”. Pas de transformation, pas d'agents, pas de battage — juste une tâche de classification répétitive qui ne vous mange plus vos après-midis.
